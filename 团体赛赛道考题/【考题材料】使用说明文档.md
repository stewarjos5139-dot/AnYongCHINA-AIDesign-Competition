## 一、业务场景背景

### 1.1 痛点描述

在日常审计对账工作中，审计师经常需要核对来自不同系统的数据：

- **A 系统（企业 ERP）**：存储正式的客户/供应商全称，如「安永华明会计师事务所（特殊普通合伙）」
- **B 系统（银行流水/外部平台）**：存储非标准化的对方户名，如「安永华明」、「安永华明会计师事务所(特殊普通合伙)」、「安永华明（北京）」等

由于以下原因，传统的 `VLOOKUP` / `XLOOKUP` 精确匹配完全失效：

| 差异类型 | A系统（标准名） | B系统（野名字） |
|----------|----------------|----------------|
| 简称 vs 全称 | 中国石油天然气股份有限公司 | 中国石油天然气 |
| 括号格式不同 | 阿里巴巴（中国）网络技术有限公司 | 阿里巴巴(中国)网络技术有限公司 |
| 多余空格 | 华为技术有限公司 | 华为 技术 有限公司 |
| 附加备注 | 安永华明会计师事务所（特殊普通合伙） | 安永华明会计师事务所（北京分所） |
| 错别字/近音字 | 北京字节跳动网络技术有限公司 | 北京字跳网络技术有限公司 |
| 缺少后缀 | 万科企业股份有限公司 | 万科企业 |
| 特殊符号 | 中国平安保险（集团）股份有限公司 | 中国平安保险(集团)股份有限公司 |

**人工逐条肉眼核对 100+ 条记录，耗时数小时且极易出错。**

### 1.2 你的任务

编写一个**模糊匹配脚本/工具**，引入字符串相似度算法，自动完成 A、B 两系统的智能容错对齐，输出匹配结果。

## 三、任务要求

### 3.1 核心功能（必须实现）

1. **数据读取**：一键读取 A、B 两表数据
2. **文本预处理**：自动清洗名称字段：
   - 移除多余空格（连续空格 → 单个空格，首尾去空格）
   - 统一全角/半角括号：`（）→ ()` 或 `() → （）`
   - 统一大小写（如有英文部分）
   - 移除/忽略不可见字符（`\t`, `\n`, `\r`, `\xa0` 等）
   - 移除特殊符号干扰（如多余的标点）
3. **模糊匹配**：对 A 系统每条记录的「客户名称」与 B 系统每条记录的「对方户名」进行相似度计算
4. **最佳匹配确定**：为每条 A 系统记录找到 B 系统中相似度最高的对应记录
5. **结果分类**（按相似度从高到低分为 5 类）：
   - **完全匹配（100%）**：名称清洗后完全一致
   - **高度匹配（≥90%）**：可直接确认
   - **中低匹配（70% ≤ score < 90%）**：建议人工复核
   - **低置信度匹配（<70%）**：需逐条核实
   - **A 系统独有**：在 B 系统中无匹配（所有候选相似度均 < 最低阈值，建议设 60%）
   - **B 系统独有**：在 A 系统中无匹配
   
   > **阈值说明**：≥90% 为高度匹配，70% 为分界线（含 70% 归入中低匹配），<70% 归入低置信度匹配。选手可在工具中提供可调节阈值（加分项）。

### 3.2 加分功能（非必须，实现可加分）

- ✅ 支持多种相似度算法切换（Levenshtein / Jaro-Winkler / Cosine / difflib）
- ✅ 匹配结果可视化展示（高亮标注不同置信度）
- ✅ 支持手动调整匹配阈值
- ✅ 一键导出标准化 Excel 成果文件
- ✅ 匹配统计仪表盘（饼图/柱状图展示匹配分布）
- ✅ 对未匹配记录给出最佳候选建议（如"最佳候选：安永华明，相似度 58.2%"）
- ✅ 批量处理——支持拖入多个 Excel 文件
- ✅ GUI 界面 / Web 界面（非命令行）

### 6.1 推荐技术栈

| 技术 | 用途 |

| **Streamlit** / **PyQt** / **Tkinter** | 图形界面（加分项） |

### 6.2 推荐匹配流程

```
┌──────────┐    ┌──────────┐
│ A系统数据 │    │ B系统数据 │
└────┬─────┘    └────┬─────┘
     │               │
     ▼               ▼
┌──────────┐    ┌──────────┐
│ 文本预处理│    │ 文本预处理│  ← 去空格、统一括号、去特殊字符
└────┬─────┘    └────┬─────┘
     │               │
     └───────┬───────┘
             ▼
     ┌──────────────┐
     │ 笛卡尔积比对  │  ← A每一条 × B每一条
     │ (100 × 95)   │
     └──────┬───────┘
             ▼
     ┌──────────────┐
     │ 相似度计算    │  ← Levenshtein / Jaro-Winkler / SequenceMatcher
     └──────┬───────┘
             ▼
     ┌──────────────┐
     │ 最佳匹配选取  │  ← 每条A记录选相似度最高的B记录
     └──────┬───────┘
             ▼
     ┌──────────────┐
     │ 置信度分类    │  ← ≥90% 高 / 70-90% 中 / <70% 低
     └──────┬───────┘
             ▼
     ┌──────────────┐
     │ 结果输出      │  ← 4个Sheet的Excel文件
     └──────────────┘
```

### 6.3 相似度算法对比

| 算法 | 适合场景 | 优缺点 |
|------|----------|--------|
| **Levenshtein 距离** | 错别字、少量字符差异 | 经典算法，但字符串很长时区分度下降 |
| **Jaro-Winkler** | 前缀相似（适合公司简称） | 对前缀相同的字符串敏感，适合公司名匹配 |
| **SequenceMatcher** | 任意文本差异 | Python 内置，基于最长公共子序列 |
| **TF-IDF + Cosine** | 大量文本、多词组合 | 将名称拆词后比较，适合中文分词场景 |
| **Token Sort Ratio** | 词序不同但内容相同 | 对词序不敏感（thefuzz 内置） |

**建议**：至少使用两种算法取加权平均，提高匹配鲁棒性。

## 八、常见问题 FAQ

**Q1：是否可以使用现成的模糊匹配库（如 thefuzz）？**
A：可以。AI 工具不限，也不限制使用开源库。重点是理解算法原理并正确应用。

**Q2：数据中是否包含英文名称？**
A：本次数据主要为中文企业名称，但可能包含英文括号、英文字母等元素。

**Q3：一个 A 系统记录可以匹配多个 B 系统记录吗？**
A：默认按"一对一"匹配（每条 A 记录取最佳匹配的 B 记录）。如果需要支持"一对多"请在设计文档中说明。

**Q4：金额有差异怎么处理？**
A：模糊匹配工具的核心是**名称匹配**，金额差异在匹配完成后展示即可，不作为匹配依据。

**Q5：匹配阈值可以自己设定吗？**
A：可以。默认建议 90%/70% 分档，但你可以在工具中提供可调节阈值——这是一个加分项。

**Q6：Python 不熟悉，可以用 Excel VBA 或 R 语言吗？**
A：可以。编程语言不限，只要工具能独立运行并完成全部核心功能即可。
